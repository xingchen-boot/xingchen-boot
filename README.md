# 四、阅读教材后的 5 个问题

- 1.软件工程方法学的核心思想是什么？它是如何指导软件开发全生命周期的？

- 2.在软件生命周期的各个阶段（如需求分析、设计、编码、测试等），质量保证的关键措施分别有哪些？

- 3.软件项目的成本估算和进度计划制定，通常会受到哪些主要因素的影响？如何提高其准确性？

- 4.面向对象方法与传统的结构化方法在软件开发过程中有哪些显著差异？各自的适用场景是什么？

- 5.软件维护在整个软件生命周期中占据很大比重，导致软件需要维护的常见原因有哪些？如何高效地进行软件维护？

# 五、渴望得到的收获

- 1.构建系统的软件工程知识体系：希望能跳出 “单纯写代码” 的局限，系统掌握软件工程全生命周期（需求分析、设计、编码、测试、维护）的核心逻辑与方法，理解不同阶段的工作重点、工具应用及标准流程，让技术学习从 “零散知识点” 整合为 “结构化知识框架”，为后续复杂项目开发打下理论基础。​

- 2.提升工程化实践能力：期待通过课堂案例分析、小组项目等形式，将教材中的方法论落地 —— 比如学会用 UML 绘制需求模型图、用测试工具设计完整的测试用例、用版本控制工具（如 Git）规范协作流程，真正把 “软件工程理论” 转化为 “解决实际问题的能力”，避免 “懂理论但不会落地” 的困境。​

- 3.培养协作与项目管理思维：渴望在团队项目中，不仅做好技术实现，还能理解 “项目管理者视角”—— 比如如何拆解任务、评估开发周期、应对需求变更、协调团队分工，同时提升跨角色沟通能力（如与 “需求方” 对齐需求、与 “测试人员” 配合定位问题），为未来参与或主导团队项目积累经验。​

- 4.建立质量与效率并重的开发意识：希望能养成 “提前规避问题” 的思维，而非 “事后补救”—— 比如在编码前重视需求评审、在设计阶段考虑可维护性、在测试环节覆盖关键场景，理解 “高质量软件不仅是功能能用，更要兼顾稳定性、可扩展性与用户体验”，让自己写出的代码既有 “技术深度”，也有 “工程温度”。
